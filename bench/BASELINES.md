# Offline baseline measurements

Generated by `uv run python bench/report.py` from `bench/out/*.json`. These tables report offline baselines; any separate live-pass status is recorded below.

Jaro-Winkler and TF-IDF thresholds maximize F1 on the **same truth being scored**. They are in-sample upper bounds for these fixed best-match methods, not held-out accuracy estimates or general upper bounds for string matching. Threshold tuning evaluates all distinct scores, keeps ties together, and prefers fewer links when F1 ties.

Both similarity baselines choose one right record per left; several left records may choose the same right record. Ties select the earliest right source row. Their recall is consequently limited on truth with multiple right matches per left. Exact matching emits every pair equal after `fields.normalize` in every `on` field; a missing or empty field prevents a match. Scoring counts unique ID pairs and uses zero for rates with an empty denominator.

Jaro-Winkler compares joined normalized `on` fields only within nonempty shared first-character blocks. TF-IDF fits character 2–4-grams jointly on left and right, compares positive cosine pairs using sparse row chunks, and selects the best per left. Fields have no tuned weights. The first-character rule can lose true matches; the table reports that loss explicitly.

## Data checks and interpretation

- **febrl4**: Two records match when they were generated from the same underlying person in FEBRL, despite errors or missing identifying information. Sharing a surname or an address alone does not establish a match. Duplicate truth pairs removed: 0; duplicate records excluding ID, left/right: 0/0. IDs are unique within each source and every truth ID was verified.
- **dblp-acm**: Two bibliographic records match when they describe the same published paper. A different paper by the same authors or with a similar title is not a match. Duplicate truth pairs removed: 0; duplicate records excluding ID, left/right: 40/22. IDs are unique within each source and every truth ID was verified.
- **abt-buy**: Two listings match when they offer the same product model. The same product line in a different size, color, capacity, software version or license bundle is not a match. Duplicate truth pairs removed: 0; duplicate records excluding ID, left/right: 0/12. IDs are unique within each source and every truth ID was verified.
- **amazon-google**: Two listings match when they offer the same product model. The same product line in a different size, color, capacity, software version or license bundle is not a match. Duplicate truth pairs removed: 0; duplicate records excluding ID, left/right: 0/140. IDs are unique within each source and every truth ID was verified.
- **nber-firms**: A patent assignee matches a Compustat company when the historical NBER assignee-to-Compustat crosswalk assigns it to that company, including subsidiary-to-parent links. This is the crosswalk's historical corporate association, not necessarily the same legal entity or its present owner. Duplicate truth pairs removed: 3; duplicate records excluding ID, left/right: 3/10. IDs are unique within each source and every truth ID was verified.

DBLP-ACM's downloaded DBLP2.csv has 2,616 rows; the Leipzig web page says 2,614. This report uses the actual archive without silently deleting records. Product mappings include multiple matches, and identical descriptions under different IDs are retained.

NBER firm links include parent/subsidiary and historical associations. The prepared set contains only labeled companies, and unlisted pairs are assumed negative. These labels are not a clean same-legal-entity or current-ownership gold standard. See [FIRM_DATA.md](FIRM_DATA.md) for the search, terms, construction, and limitations. All sources and download hashes are recorded in each dataset's meta.json.

Exact matching can have zero product recall because prices and descriptions differ or are missing. Jaro-Winkler is especially weak on Abt-Buy's concatenated descriptions. The reported results use the declared fields without dataset-specific similarity weights.

Reproduce full runs:

```sh
uv sync --group bench
uv run python bench/prepare.py
for name in febrl4 dblp-acm abt-buy amazon-google nber-firms; do
  uv run python bench/run.py --dataset "$name" --budget 0.10
done
uv run python bench/report.py
```

The harness writes one JSON file per dataset, so a sampled rerun replaces that dataset's previous report. Sampling is explicit in JSON and this table; rerun without `--sample` to restore full-data measurements. `--sample 1000` keeps all right-side competitors and uses seed 0. No current dataset has more than 60,000 left-times-10 possible candidates.
